# وظائف المشرف ونطاقه التشغيلي

Enterprise Sales & Distribution ERP | الإصدار 0.1 | مرحلة تحليل وجمع المتطلبات

مرجع للمحلل والمصمم والمبرمج؛ يفصل الوظائف عن السياسات والإعدادات القابلة للتهيئة.

---

## 1. تعريف الدور

المشرف هو مدير التشغيل الميداني لفريق من المناديب ضمن نطاق تنظيمي وجغرافي. يمكن أن يشرف على أكثر من مندوب وحتى 10 مناديب وفق النموذج الحالي، لكن العدد نفسه إعداد قابل للتهيئة في ERP.

مسؤولياته الأساسية: التخطيط، الأهداف، GPS، الأداء، المخزون، الصندوق، العهد والأصول، العملاء والديون، الملاحظات والمراسلات.

## 2. السياق التنظيمي

- المشرف يربط بين مدير المبيعات والمناديب
- نطاقه: فريق من المناديب ضمن منطقة جغرافية
- ي report لمدير المبيعات
- يدير 1-10 مناديب (قابل للتهيئة)

## 4. التخطيط والأهداف والمتابعة

| المجال | أمثلة | المصدر |
|--------|-------|--------|
| خطة السير | عملاء، ترتيب الزيارات، الفترة | Route Plan |
| هدف كمي | كراتين/وحدات/منتجات | Sales |
| هدف مالي | مبيعات/تحصيل | Invoices/Collections |
| هدف تشغيلي | زيارات/نسبة تنفيذ | Visits/GPS |
| فترة الهدف | يومي/أسبوعي/شهري/سنوي | Target Configuration |

## 5. GPS والأداء

GPS عند المشرف ليس خريطة فقط؛ بل يربط الموقع والوقت والزيارة وخطة السير والإنجاز. يجب تمييز البيانات اللحظية عن آخر بيانات متزامنة عند العمل Offline/Online.

| البيانات | الاستخدام |
|----------|-----------|
| الموقع | تحديد موقع المندوب |
| الوقت | الوصول/المغادرة والحركة |
| الزيارة | مطابقة الخطة |
| المسار | قياس الالتزام |
| الإنجاز | ربط النشاط بالهدف |
| Sync State | بيانات حداثة البيانات |

## 6. مخزون المشرف

مخزون المشرف ليس إلزاميًا. عند تفعيله، يستطيع مناديب المنطقة طلب بضاعة منه وفق سياسة المؤسسة. كل استلام أو تحويل ينتج حركة مخزون موثقة.

| الحالة | السلوك |
|--------|--------|
| مفعّل | طلبات من المناديب إلى مخزون المشرف |
| غير مفعّل | الطلب يتجه إلى المصدر المحدد في السياسة |
| تحويل | صلاحيات وحدود كمية/منتج |
| استلام | تحديث عهدة المستفيد حسب Workflow |

## 7. صندوق المشرف

صندوق المشرف كيان مالي مستقل عند تفعيله. الرصيد ينتج من حركات مالية ولا يعدل مباشرة.

| العنصر | المتطلب |
|--------|---------|
| Opening | رصيد افتتاحي معتمد |
| Movements | استلام/توريد/تحويل/تسوية |
| Closing | يومي/دوري/حسب السياسة |
| Differences | تسجيل ومراجعة الفروقات |
| Audit | المستخدم والوقت والسبب |

## 8. العهد والأصول

يمكن للمشرف طلب أصل مثل Laptop وتحديد المستفيد والمندوب. بعد موافقة المدير يتم توثيق العهدة ورفع الوثائق والصور والفيديوهات وربطها بسجل الأصل.

| البيانات | يجب حفظها |
|----------|-----------|
| Asset | نوع/رقم الأصل |
| Beneficiary | المستفيد |
| Assignment | المندوب/الشخص |
| Approval | من وافق ومتى |
| Handover | واقعة التسليم |
| Attachments | صور/فيديو/وثائق |
| Archive | السجل التاريخي |

## 9. تحويل المخزون

صلاحية المشرف قد تكون كاملة داخل الفريق أو محددة بمنتجات/كميات/مناديب. لذلك يجب أن تكون Permission + Policy وليست صلاحية ثابتة.

| الإعداد | مثال |
|--------|------|
| Scope | Team / Selected Representatives |
| Product Scope | منتجات محددة |
| Quantity Limit | حد لكل عملية/فترة |
| Approval | مطلوب/غير مطلوب |
| Receiving | تأكيد المستفيد |

## 10. تحويل العملاء ومسؤولية الديون

عند التحويل يتوقف الإسناد السابق ويصبح الإسناد الجديد فعالًا. وفق المتطلب الحالي تصبح مسؤولية التحصيل الحالية على المندوب الجديد، لكن لا يجوز حذف تاريخ الفواتير والديون السابقة.

إذا كانت المؤسسة تشترط إعادة إدخال بيانات العميل عند التحويل، ينفذ ذلك كإجراء قابل للتهيئة؛ أما هوية العميل وتاريخه فيبقيان محفوظين.

## 11. أعمار الديون

| الشريحة | الغرض |
|---------|-------|
| غير مستحق | متابعة الدين ضمن المدة |
| 1–30 | متابعة مبكرة |
| 31–60 | متابعة متوسطة |
| 61–90 | متابعة متقدمة |
| >90 | أولوية تحصيل |

يظهر للمشرف Aging ضمن نطاقه مع العميل والمندوب الحالي وقيمة الدين.

## 12. العملاء المستهدفون

المندوب يضيف عميلًا مستهدفًا؛ المشرف يراجعه ويوافق/يرفعه إلى مدير المبيعات حسب Workflow، مع رفع الوثائق وأرشفتها. العميل المستهدف ليس بالضرورة عميلًا رسميًا.

## 13. إيقاف المندوب والعميل

الإيقاف لا يعني الحذف. يجب حفظ التاريخ. وإذا كان للمندوب مخزون أو صندوق أو عهدة، فإن الإيقاف النهائي قد يتطلب جردًا وتسوية وتسليمًا حسب سياسة المؤسسة.

| الكيان | حالات نموذجية |
|--------|--------------|
| Representative | Active / Suspended / Inactive |
| Customer | Active / Suspended / Inactive |
| Custody | Open / Pending Settlement / Closed |

## 14. ملاحظات المندوبين والمراسلات

المشرف يستطيع إضافة ملاحظات أداء/إدارية مع التاريخ والمستخدم والمندوب والمرفقات، ويمكن تحديد من يراها بالسياسة. كما يستطيع التواصل داخل النظام مع المناديب ومدير المبيعات والجهات المسموح بها، مع المرفقات والأرشفة.

## 17. قواعد تنفيذ إلزامية للمبرمج

- لا تحذف السجل التاريخي عند إيقاف مندوب أو عميل.
- لا تعدل رصيد المخزون أو الصندوق مباشرة؛ الرصيد ينتج من الحركات.
- افصل إنشاء الطلب عن الموافقة والتنفيذ والاستلام عندما تتطلب السياسة ذلك.
- طبّق نطاق المشرف على المناديب والعملاء والبيانات ما لم تمنحه المؤسسة صلاحية أوسع.
- كل عملية حساسة تسجل المنفذ والوقت والحالة والمرجع.
- السيارة والمخزن والصندوق وعدد المناديب وسياسات التسوية ليست علاقات ثابتة؛ يجب دعم التهيئة.
- لا تنشئ صفحة لكل وظيفة آليًا؛ بعض الوظائف Actions/Views داخل Module واحد.

## 19. نقاط تحتاج تثبيتًا لاحقًا

- هل خطة السير تحتاج اعتمادًا قبل نشرها؟
- هل يمكن تعديل الأهداف أثناء الفترة ومن يعتمدها؟
- ما تردد GPS؟
- هل مخزون المشرف إلزامي أم اختياري؟
- من يعتمد العهدة؟
- هل تحويل العميل يحتاج مدير المبيعات؟
- كيف تحدد الديون التي تنتقل مسؤوليتها؟
- هل ملاحظات المشرف سرية؟
- ما حدود صندوق المشرف؟
- ما حدود تحويل المخزون؟

## 20. الخلاصة

المشرف مدير تشغيل ميداني وليس مجرد مستوى موافقة. يجب أن يدعم النظام التخطيط والأهداف والمتابعة والجغرافيا والأداء والمخزون والصندوق والعهد والعملاء والديون والمراسلات.

في ERP متعدد المؤسسات، هذه الوظائف Capabilities، بينما طريقة تشغيلها وحدودها واعتماداتها هي Configuration + Policy + Workflow + Permissions. لذلك يجب أن يكون التنفيذ مرنًا دون إعادة بناء النظام لكل مؤسسة.
